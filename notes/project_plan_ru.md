# Рабочий план: ridge CCA в statsmodels

Источник требований — [proposal](../proposal/proposal_submitted.pdf), особенно
разделы I, IV–VIII, и [комментарий](../proposal/feedback.md).
Актуальный отчёт для владельца проекта — [README](../README.md).

## Обязательный результат

1. Расширить существующий CanCorr ridge-штрафами. При нулевых штрафах сохранить
   совместимость на полноранговых данных; при положительных поддержать p > n.
2. Реализовать K-fold cross-validation для выбора двух штрафов по held-out
   correlation. Centering/scaling и другие обучаемые операции — внутри folds.
3. Реализовать **permutation test для каждой канонической корреляции**, как
   указано в proposal. Обосновать процедуру для второй и последующих корреляций,
   как требует комментарий преподавателя. Существующую Wilks' Λ F-аппроксимацию
   сохранить в применимом классическом режиме; не переносить её на ridge без обоснования.
4. Подготовить пример Nutrimouse, второй реальный набор, синтетику с известной
   истиной, numerical checks с R, сравнения качества/времени и документацию.
5. Поставить tested PR в statsmodels либо предусмотренный proposal устанавливаемый
   fork с tests, CI, documentation и benchmark. Результаты оформляются для владельца
   проекта; подготовка обращений к преподавателю не входит в работу.

## Рабочие решения и границы

- Основной reference ridge — R CCA::rcc; classical compatibility — CanCorr.
  R и сторонние CCA-пакеты не становятся runtime-зависимостями statsmodels.
- Covariance denominator n−1; trace-relative additive ridge. Вывод и различие
  penalized roots / Pearson correlations — в методической записке.
- Число folds, сетка штрафов, seeds и дизайн итоговой проверки фиксируются до
  просмотра итоговых результатов. Конкретные параметры прежних пилотов —
  решения ассистента, а не обязательные числа из proposal.
- Вложенная CV может быть способом оценки, но не добавлена как самостоятельное
  требование.
- Если обоснование permutation test для второй и последующих корреляций при
  ridge-регуляризации не получается, это нерешённая
  задача, которую нужно честно описать владельцу проекта. Сужение обязательства
  не считается автоматически принятым и не заменяется черновиком письма.

## Проверка значимости второй и последующих канонических корреляций

Это конкретная задача из комментария: «The statistical testing procedure for
the second and later correlations also needs justification».

Например, если первая связь существует, а вторая отсутствует, permutation test
второй корреляции не должен систематически объявлять её значимой из-за первой.
Обычное перемешивание строк одной таблицы разрушает все связи, включая первую;
поэтому его корректность для второй и следующих корреляций нельзя предполагать.

В рамках этапов 1 и 4 требуется:

1. Определить нулевые гипотезы. Для k-й позиции рассмотреть
   H_k: ρ_k = … = ρ_m = 0 при допустимом наличии предыдущих связей;
   m = min(p,q), ρ — популяционные канонические корреляции.
2. Обосновать статистику, допустимые перестановки и учёт предыдущих связей.
   Изучить подход Winkler et al. (2020) как методический источник для обычного
   CCA; отдельно установить применимость к ridge и подбору штрафов. Это ещё
   не выбранная и доказанная процедура для нашего расширения.
3. Учесть, что процедура проверяет несколько корреляций: определить, какую
   ошибку контролируют p-values и как обрабатываются множественные проверки.
   Если штрафы выбираются по данным, повторять их выбор в перестановках.
4. На синтетике с известной истиной из proposal проверить отсутствие всех
   связей, одну настоящую связь с нулевыми последующими и несколько настоящих
   связей. Измерить type-I error при α=0.05 и мощность с Monte Carlo uncertainty.
5. Реализовать permutation test только с явно описанными условиями и результатами
   этих проверок. Отсутствие обоснования означает невыполненный пункт proposal,
   а не разрешение заменить его тестом только первой корреляции.

Источник для исследования: [Winkler et al., Permutation Inference for Canonical
Correlation Analysis](https://arxiv.org/html/2002.10046v3).
